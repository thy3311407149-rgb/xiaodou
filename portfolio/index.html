Personal Knowledge Understanding Layer

让信息真正成为你的知识

文件、录音、笔记每天都在增加。保存下来，并不等于理解了，也不等于以后还能用上。小豆要做的是一条更长的路径：先理解，再沉淀成知识，让它们彼此关联，在需要时被重新看见。

  2. 沉淀
  3. 关联
  4. 回顾

小豆不是一轮对话。它是一套个人知识理解系统。后面两步仍在 Beta 1.2，前面的知识对象和语义关联已经跑通。

01

我们真正想解决的，不是“信息太多”，而是“信息没有成为知识”

用户拥有越来越多的信息，却没有获得与之匹配的知识能力。

PDF 会议录音 课程 文章 随手记录
大量信息
分散 难理解 难关联 易遗忘 需要时找不到
  1. PDF、会议录音、课程、文章和随手记录不断进入。
  2. 它们汇成大量信息。
  3. 随后变成分散、难理解、难关联、易遗忘的孤岛。
  4. 真正需要时，又找不到。
02

现有工具停在总结之前，长期知识还没有发生

保存、搜索、总结、对话，各自都有用。真正困难的是：让不同时间产生的信息持续沉淀、相互关联，并在未来重新产生价值。

内容产生

文件、录音、笔记在不同时刻出现。

内容存储

文件夹、笔记软件把原文留下。

AI 总结

一次阅读被压缩成一段摘要。

Knowledge Gap

摘要结束之后，知识并没有继续活着。

长期知识

可回溯、可关联、以后还能用。

  • 这里不比较具体产品，也不引用未经核实的份额。
  • 缺口是机制上的：一次处理完成了，个人知识却没有开始。

小豆

Personal Knowledge Understanding Layer。它站在原始信息和个人知识之间，负责理解、结构、关联和再次使用。

输入信息。 当前真正进入理解管道的是 PDF。录音和随笔在 Beta 1.2 接入同一条路径。

AI 理解。 文本被清洗、分块，再抽出可以独立成立的知识点。摘要只是中间结果。

形成 Knowledge。 知识点被去重、聚合、抽象，变成可以保存和检索的知识对象，并进一步识别核心知识。

向小豆提问。 Beta 1.2 希望基于已经沉淀的知识回答，并带出引用。当前界面仍是静态演示。

05

Knowledge 是产品核心

小豆把一份文档拆成可以单独成立、可以长期保存、也可以再被归纳的对象。点开每一层，看它是什么、为什么需要、在产品里怎么用。

Document

它是什么
用户的原始内容。当前是按页保存的 PDF 文本。
为什么需要
后面所有理解都必须能回到这份原文，不能只留下模型的转述。
在产品中如何使用
上传 PDF 后抽取文本、清洗，再进入分块。它是来源，不是最终的知识。

Chunk

它是什么
AI 理解内容时使用的基础文本单元，带有顺序、页码和长度。
为什么需要
整篇文档太长，无法稳定地抽出彼此独立的意思。分块是理解的工作单位。
在产品中如何使用
后续知识点只能引用真实存在的 chunk 序号，并附上原文中的连续片段。

Knowledge Point

它是什么
从内容里抽出的、具有独立语义和价值的知识单元。可以是几句话，也可以是一句话里的几个独立意思。
为什么需要
过渡句和修辞没有长期价值。先把值得留下的意思单独拿走。
在产品中如何使用
每个知识点带着 source quote：必须是原文连续片段，不能改写。这是溯源的第一层。

Knowledge

它是什么
把知识点去重、聚合、抽象之后，形成的可长期沉淀、检索和关联的知识对象。
为什么需要
知识点仍然贴近局部原文。知识对象才是以后会被嵌入、召回和关联的东西。
在产品中如何使用
高度重复的点会合并。一个点也可以支撑多个知识。数字、时间、人物、条件和预测不得被改写成更确定的说法。

Core Knowledge

它是什么
从多个 Knowledge 中进一步识别出的高价值核心知识。一份文档原则上 3 到 6 条；不够就不凑。
为什么需要
不是每条知识都同样重要。核心知识是用户以后最值得重新看见的那一层。
在产品中如何使用
类别只包括结论、关键事实、定义、逻辑关系、重要清单和核心论点。多个知识可以被二次抽象成一条核心知识，并记录来源序号。

07

关联要回答“为什么”，不只是“像不像”

Embedding 负责找到可能相关的知识，Agent 负责判断为什么相关。向量相似度高，并不等于存在真实的信息关系。下面四种关系来自当前 Agent 的判断集合。

示意网络

节点内容来自产品里的认知负荷示例，只用于说明关系，不是实时知识库。

同主题补充

SAME_TOPIC_COMPLEMENT。同一主题下互相补全，例如把“外化成可检索笔记”补进工作记忆这条知识。

因果逻辑

CAUSAL_LOGICAL。前提、因果或推导承接。外在负荷下降，当前推理才有空间。

概念同源

CONCEPT_SAME_ORIGIN。共享核心概念或定义基础，而不是仅仅用了相近的词。

同类对比

SAME_CATEGORY_COMPARISON。笔记、图表、知识库都是外部存储，可以对照，但不是同一句话的复述。

  1. Embedding
  2. Candidate Retrieval
  3. AI Semantic Understanding
  4. Relation Judgment
  5. Knowledge Relation

知识写入 Qdrant 的向量是 1024 维、余弦距离。召回之后，Agent 看不到相似度数字，必须根据两边内容给出关系类型和理由。完全重复、只有主题词相似、原文无法支撑的关系，都不会被收下。

08

AI 简报 Beta 1.2

发现和提醒的管道还没有上线。知识库原型里已经能切换两条静态卡片，用来预览交叉关联和遗忘提醒，数据是写好的。

新知识遇见历史知识

  1. 一条新的 Knowledge 进入个人知识库
  2. 与更早留下的知识放在一起看
  3. AI 发现它们之间的关联
  4. 这些关联可以长成一个新的主题

已实现的 Related Knowledge 判断的是两条知识为什么相关。简报里的交叉关联更进一步：把这种关系主动交给用户，并收成主题。后者仍是规划。

过一段时间，再看见一次

  1. 过去已经理解过的知识
  2. 超过一定时间没有被使用
  3. 系统重新提醒
  4. 用户回到原始知识，而不是只看到一句提醒

遗忘提醒的具体时间规则还没有产品化。这里只说明方向：提醒必须能回到原来的知识。

12

差异在机制里

Knowledge First

产品围绕 Knowledge，而不是围绕文件列表。文件是来源。用户以后反复使用的是知识对象、它的来源和它的关系。

Active Discovery

已实现的部分会在嵌入完成后判断关系，而不是只等关键词搜索。Beta 1.2 希望把这种发现主动送到简报里。搜索本身放到下一版本。

Traceable AI

知识点必须引用原文连续片段。知识引用知识点。核心知识引用知识。生成物可以回到当时的那一页，而不是停在一段无法核对的转述。

Continuous Knowledge Loop

输入之后并不结束。

  1. 输入
  2. 理解
  3. 沉淀
  4. 关联
  5. 回顾
  6. 问答
  7. 再输入

产品希望通过长期知识积累，形成可持续增强的个人知识资产。这里没有用户规模，也不把尚未发生的积累说成已经形成的数据壁垒。

  1. 用户持续输入每一次真的留下内容
  2. Personal Content文件、以及未来的录音和随笔
  3. Knowledge Corpus被理解之后的知识对象
  4. Knowledge Structure核心知识与来源关系
  5. Semantic Relationships为什么相关，而不只是相似
  6. User Behavior回顾、提问、再次使用。大多仍在 Beta 1.2
  7. Personal Knowledge System属于这个人的知识系统

15

路线没有编造日期

每个阶段只写目标，以及代表这个阶段的能力。时间以实际交付为准。

Foundation

核心目标：让文件可以被接收，处理过程可以被追踪。

代表能力：健康检查、PDF 上传、任务状态。

PDF → Knowledge

核心目标：一份文档变成可回溯的知识对象。

代表能力：Chunk、Summary、Knowledge Point、Knowledge、Core Knowledge。

Semantic Layer

核心目标：知识能被召回，并且关系说得清理由。

代表能力：Embedding、Qdrant、Related Knowledge。

Beta 1.2

核心目标：把理解层接到每天的使用里。

代表能力：文件库、录音、随笔、问小豆、AI 简报、主题集合。

Multi-source Knowledge

核心目标：录音和随笔进入与 PDF 相同的知识管道。

代表能力：转写后的 Knowledge、结束后的说话人分离、跨来源关联。

Personal Knowledge System

核心目标：个人知识形成可以回访的结构。

代表能力：遗忘提醒成为习惯、主题持续生长、Graph 作为理解视图。

Personal AI

核心目标：小豆依据这个人的知识回答，而不是做一次无关的总结。

代表能力：带来源的问答、全局搜索。

愿景

今天，用户拥有大量信息。
未来，每一份信息都可以成为个人知识的一部分。

小豆希望成为你的 Personal Knowledge Understanding Layer。
